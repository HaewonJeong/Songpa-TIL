1. Vercel + Supabase 배포 준비

- 이 프로젝트는 이미 배포를 염두에 두고 구성돼 있음: schema.prisma 에 url(런타임) / directUrl(마이그레이션) 분리, .env.example 에 연결 문자열 형식 문서화, next.config.mjs 에서 Spring rewrite 제거됨.
- 배포 흐름 정리:
  a. Supabase 프로젝트 생성 → Transaction pooler(6543) = DATABASE_URL, Direct(5432) = DIRECT_URL
  b. 런타임 URL엔 ?pgbouncer=true&connection_limit=1 필수 (서버리스 커넥션 폭증 방지)
  c. 로컬에서 .env 를 Supabase 값으로 두고 npm run db:push + npm run db:seed + SQL 함수 설치
  d. git init → GitHub push → Vercel import → 환경변수 3개(DATABASE_URL, DIRECT_URL, SESSION_SECRET) → Deploy
- 배운 점: prisma db push / Vercel 재배포는 DB 스키마를 자동 반영하지 않음. 스키마 변경 시 로컬에서 Supabase 대상으로 db:push 를 다시 돌려야 함.

2. Next.js 서버 코드 디버깅

- 증상: route.js 에 브레이크포인트를 걸어도 안 멈춤.
- 원인: .vscode/launch.json 이 예전 Vite 시절 설정(type: chrome) 그대로였음. Chrome 디버거는 브라우저 JS만 잡고, Route Handler / 서버 컴포넌트 / src/server/* 는 Node.js에서 실행되므로 안 걸림.
- 배운 점: Next.js는 코드가 두 군데서 돈다 — 서버(Node 디버거 필요) vs 클라이언트('use client', Chrome 디버거). launch.json 을 NODE_OPTIONS=--inspect 방식 + 클라이언트/풀스택 compound로 교체.
- 추가 함정: 프로젝트 경로에 공백·한글(JJCinmenaFront - 복사본)이 있으면 Windows에서 소스맵 경로 매핑이 깨질 수 있음.

3. Prisma 쿼리 로깅 & 생성 SQL 이해

- src/server/prisma.js 에 log: ['query','error','warn'](개발), ['error'](운영) 추가 → 터미널에 prisma:query SELECT ... 출력.
- prisma.movie.findUnique 같은 메서드는 직접 짠 코드가 아니라 prisma generate 가 스키마 보고 자동 생성한 것. 실제 SQL은 JS에 없고 Rust 쿼리 엔진(query_engine-windows.dll.node)이 만든다.
- 생성된 SQL 읽기:
  - findUnique 에도 LIMIT $2 OFFSET $3 이 붙음 → $2=1(LIMIT 1), $3=0(OFFSET 0). Prisma는 상수도 전부 파라미터로 뺌.
  - WHERE (... AND 1=1) 의 1=1 은 Prisma가 WHERE 절을 항상 유효하게 만드는 더미 조건. 옵티마이저가 제거하므로 성능 영향 없음.

4. ORM → 저장 프로시저(함수) 전환

- 회원가입(방법만): createUser() 하나만 바꾸면 Route Handler + Server Action 둘 다 커버. Postgres 함수 signup_user() + INSERT ... ON CONFLICT (email) DO NOTHING RETURNING 으로 중복 체크를 원자적으로. 비밀번호 해싱은 로그인의 verifyPassword(scrypt)와 포맷을 맞추기 위해 Node에 유지.
- 내 예매(실제 적용): getMyBookings() 가 N+1이었음 — findMany(bookings) 1번 + 예매마다 assembleDetail(bookingSeat/showtime/movie/payment) 4번 = 10건이면 41쿼리.
  - prisma/sql/get_my_bookings.sql 에 get_my_bookings(p_user_id bigint) 함수 작성 (JOIN + array_agg 좌석 + 날짜/시간 to_char 포맷 + 홀드 잔여시간까지 SQL에서 계산).
  - bookingService.js 의 getMyBookings 를 prisma.$queryRaw 호출 + 결과 매핑으로 교체 → 1쿼리.
  - assembleDetail 은 getBookingDetail(단건)에서 계속 쓰여서 유지.
- 배운 점:
  - Prisma는 함수/프로시저를 관리하지 않음 → DB마다 SQL 수동 실행 (db push 는 함수를 안 지움).
  - $queryRaw 태그드 템플릿은 값을 자동 파라미터 바인딩 → SQL 인젝션 안전.
