# 2026-09-08 수업 108일차
### 학습 내용

JJCinema 백엔드를 무료로 배포하기 위한 DB 선택 리서치: Neon vs Supabase 비교
두 서비스의 무료 티어 제한(스토리지, 슬립/pause 정책, 자동/수동 재개 방식) 조사
Render 배포 경험(콜드스타트 약 50초)을 근거로, Supabase의 수동 pause 복구 방식이 포트폴리오 서비스엔 더 불리하다는 결론 도출 → Neon 선택
Spring Boot + Hibernate(HikariCP) 환경에서 Neon의 autosuspend와 커넥션 풀이 충돌하지 않도록 하는 설정(idle-timeout, minimum-idle, connection-test-query) 학습

### 느낀 점 / 배운 점

서비스 선택 시 스펙(용량, 가격)뿐 아니라 "복구가 자동인지 수동인지" 같은 운영 관점도 중요하다는 걸 배움
서버리스 DB를 실제 배포 환경(HikariCP 등 커넥션 풀 있는 구조)에 붙일 때 생기는 미묘한 문제(슬립 중 끊긴 커넥션)를 미리 파악하고 대비함

### 오늘 질문한 내용 정리

1. 무료 배포 가능 여부

- "이 상태로 Vercel에 배포하면 프론트·백엔드·DB 전부 무료로 되나?"
- Spring Boot 백엔드가 붙어 있으면 Vercel 하나로는 안 되고, 별도 서버(Render 등)가 필요하다는 점 확인

2. Spring → Next.js 백엔드 마이그레이션

- "Vercel로 배포할 수 있게 백엔드랑 DB도 바꿔줄 수 있어?"
- Spring Boot API를 호출하지 않고 Next.js Route Handler(app/api/...) 안에서 직접 구현
- DB 접근은 Prisma ORM, DB는 Supabase(PostgreSQL), 인증은 JWT 쿠키 방식으로 전환

3. 로컬 동작 확인

- "지금 로컬에서 실행 돼?"
- "DB도 새로 만든 거야? 로컬로?" → Supabase 클라우드 DB를 쓰는지, 로컬 DB인지 확인

4. 회원가입 로직 이해
- "findUnique 이거 뭐야?" → Prisma에서 unique 컬럼(예: email)으로 단일 레코드 조회하는 메서드
- "prisma.user의 user가 어디에 정의됨?" → schema.prisma의 model User { ... } 블록에서 생성됨 (prisma generate로 클라이언트에 반영)

5. 실제 DB 연결

- "진짜 DB가 있음? postgres 연결 정보 좀" → .env의 DATABASE_URL(Supabase 연결 문자열) 확인

6. Prisma에서 프로시저 사용 가능 여부

- "프리즈마에서 프로시저 쓸 수 있어?" → Prisma는 stored procedure를 직접 모델링하진 못하고, $queryRaw / $executeRaw로 raw SQL을 통해 호출하는 방식

참고로 채워 넣을 만한 "느낀 점"

- Spring(JPA/서버 상주형) 구조를 서버리스(Next.js Route Handler + Prisma) 구조로 바꾸면서, "백엔드 = 별도 서버"라는 고정관념 대신 프론트 프로젝트 안에 API를 두는 방식을 경험함
- ORM(Prisma) 사용법: 스키마 정의 → 클라이언트 생성 → findUnique 등 타입 안전한 쿼리, 복잡한 건 raw SQL로 우회
