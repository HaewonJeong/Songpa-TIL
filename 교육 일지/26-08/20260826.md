## 1. Graph Search / GraphRAG 개념 학습

### Graph Search
- 그래프(노드+간선)에서 시작점부터 목표까지 경로를 찾는 방법
- 대표 방식: BFS(너비 우선, 최단 경로에 유리), DFS(깊이 우선, 전체 탐색에 유리)
- AI에서의 활용: 게임 AI의 다음 수 탐색, 내비게이션의 경로 탐색(A* 알고리즘) 등

### GraphRAG
- 기존 RAG(문서를 청크로 잘라 벡터 유사도로 검색)의 한계를 보완한 기법
- 문서 안의 개체(entity)와 관계(relation)를 그래프로 미리 추출해두고, 질문이 들어오면 그래프를 탐색해 연결된 정보까지 함께 찾아 답변에 활용
- 단순 조회보다 "여러 정보를 종합해야 하는" 복합 질문에 더 강함

### 배운 점
새로운 개념을 배울 때, 이미 알고 있는 프로젝트 구조(팀원이 만든 RAG 챗봇)와 연결지어 생각하면 이해가 훨씬 빨라진다는 것을 다시 확인했다.

## 2. QuizGenerationClient.java 복습

이미 작성했던 코드를 처음부터 다시 짚어보며 각 구성 요소의 역할을 정리했다.

```
생성자(QuizGenerationClient)
- 클래스가 처음 만들어질 때 딱 한 번 실행됨
- @Value로 application.yml의 agent.base-url, agent.api-key를 주입받아
  RestClient를 미리 준비해두는 역할

generateQuiz(String ingredient) — 일반 메서드
- 호출할 때마다 실행됨 (여러 번 호출 가능)
- 이미 준비된 restClient로 실제 FastAPI 요청을 수행
```

### `.retrieve()`의 의미
- `.get()`, `.uri(...)`까지는 요청을 "준비"하는 단계
- `.retrieve()`를 호출하는 시점에 실제 네트워크 통신이 일어나며 응답을 받아옴
- 이후 `.body(QuizGenerationResult.class)`로 응답 JSON을 자바 객체로 자동 매핑

### AGENT_BASE_URL 관련 재점검
- `application.yml`의 `${AGENT_BASE_URL:http://localhost:8000}`에서, localhost는 값이 없을 때의 "기본값"일 뿐이며 실제 배포 환경에서는 별도의 환경변수 값으로 대체된다는 것을 재확인
- nginx가 Elastic Beanstalk 배포 시 자동 설치되는 리버스 프록시로, 외부 요청을 내부 애플리케이션 포트(예: 8080)로 전달해주는 역할을 한다는 것을 다시 정리

## 3. FastAPI 퀴즈 생성 코드 구조 재점검

세 파일의 역할 분담을 다시 명확히 정리했다.

```
quiz_generation_prompt.py : 응답 JSON의 형식(statement, answer, 
                              explanation, confidence)을 실제로 
                              "정의"하는 곳 (OpenAI에게 이 형식으로 
                              답하라고 프롬프트에 명시)

quiz_generation_service.py : 그 형식이 지켜졌을 것이라 "믿고" 
                               응답을 파싱만 함 (필드명을 직접 
                               정의하지 않음)

quiz.py (라우터)           : service의 결과를 그대로 반환, 
                               FastAPI가 자동으로 JSON 응답 변환
```

### `_strip_code_block` 함수 재복습

```python
def _strip_code_block(text: str) -> str:
    text = text.strip()
    if text.startswith("```"):
        text = text.removeprefix("```json").removeprefix("```").strip()
        text = text.removesuffix("```").strip()
    return text
```

- `strip()`으로 앞뒤 공백 제거
- `startswith("```")`로 코드블록 여부 확인
- `removeprefix`/`removesuffix`는 조건에 안 맞으면 아무 일도 하지 않는 안전한 명령이라는 것을 재확인
- LLM이 마크다운 코드블록으로 감싸서 응답을 줄 수 있다는 것을 가정하고 만든 방어 코드라는 목적을 다시 명확히 했다.

### 배운 점
같은 코드를 여러 번 다시 짚어보면서, "형식을 정의하는 부분"과 "그 형식을 믿고 사용하는 부분"이 서로 다른 파일에 분리되어 있다는 설계 원칙을 더 명확하게 이해하게 되었다. 이는 프롬프트가 바뀌어도 서비스 로직은 그대로 유지될 수 있다는 장점으로 이어진다는 것을 확인했다.

## 오늘 배운 점 정리

1. Graph Search와 GraphRAG는 "관계 정보를 어떻게 탐색·활용하는가"라는 공통된 문제의식에서 출발한다는 것을 이해했다.
2. Spring의 RestClient는 "요청 준비"와 "실제 전송"이 명확히 분리된 API 설계를 갖고 있으며, `.retrieve()`가 그 경계 지점이라는 것을 재확인했다.
3. 배포 환경의 URL 설정은 로컬 개발용 기본값과 실제 운영값이 다를 수 있다는 것을, nginx 리버스 프록시 구조와 함께 다시 정리했다.
4. 이미 작성한 코드라도 한 줄씩 다시 짚어보는 복습이, 설계 의도(형식 정의와 사용의 분리, 방어 코드의 목적)를 더 깊이 이해하는 데 도움이 된다는 것을 체감했다.
